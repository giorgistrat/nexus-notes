Rendering Strategies and Hosting

How you render a React app decides what kind of host you need. The key question for each strategy: is the output finished at build time, or does code have to run on every request?

The Four Strategies

SPA (Client-Side Rendering)

  • Server sends an almost-empty index.html + JS bundle; React renders everything in the browser, then fetches JSON from an API.
  • Host: any static host + a SPA fallback. The API (if yours) is a separate backend.

SSG (Static Site Generation)

  • Pages rendered to HTML once at build time (getStaticProps in Next.js Pages Router, Astro, Gatsby). Browser downloads the JS for those components and hydrates the page.
  • Host: static host. Each page is a real .html file, so no fallback is needed for known routes.

SSR (Server-Side Rendering)

  • Pages rendered to HTML on every request (getServerSideProps, renderToString / renderToPipeableStream from react-dom/server).
  • The browser still downloads JS for every component and hydrates the whole tree. After that it behaves like a SPA that fetches JSON.
  • SSR answers “how do we get HTML fast for the first view?”
  • Host: must run code per request (serverless, edge, or Node server).

RSC (React Server Components)

  • Server components run only on the server. Their output is a serialized React tree (the RSC payload), not HTML.
  • Their code, and libraries they import, never ship to the browser. They can read the DB / file system directly, no API layer.
  • Only 'use client' components ship JS and hydrate.
  • On navigation the client fetches a new RSC payload and merges it into the page without losing client state.
  • RSC answers “which components run where?”, a different axis from SSR.
  • Host: must run code per request (render + stream components, handle server-action POSTs).

RSC vs SSR: Complementary, Not Replacements

SSRRSC
OutputHTMLSerialized React tree (stream)
Component JS sent to browserAll componentsOnly client components
HydrationWhole pageOnly client components
Data fetchingBefore render (getServerSideProps) or via APIDirectly inside server components
NavigationClient fetches JSONClient fetches a new RSC payload

Next.js App Router uses both: it renders server components to an RSC payload, then SSRs that payload to HTML for the first load. Subsequent navigations fetch RSC payloads only.

Timeline

  • Pre-2020: Next.js Pages Router has SSR (getServerSideProps) and SSG (getStaticProps); no RSC.
  • Dec 2020: React team announces Server Components (demo/RFC).
  • Oct 2022: Next.js 13 introduces the App Router built on RSC (beta); stable in 13.4 (May 2023).
  • Dec 2024: React 19 stable; RSC and server actions become an officially stable part of React.

Why RSC Always Needs a Server

React itself only ships the serialization primitives (e.g. in react-server-dom-esm / -webpack):

  • renderToPipeableStream: turn server components into a stream.
  • createFromFetch: browser reads that stream and renders it.
  • decodeReply: decode arguments for server actions.

React has no HTTP server, router, or file serving. Something must:

  1. Send the HTML document.
  2. Serve the client JS modules.
  3. Respond to page requests with the streamed RSC payload.
  4. Accept action POSTs and call the right server function.

Frameworks (Next.js, React Router) hide this. Using React “directly” for RSC means building that framework yourself, which is exactly what the Epic React RSC workshop does with Hono. Hono isn’t required; Express or plain node:http would work. Its final routes look like:

Can Next.js Go on a Static Host?

Partly. With static export:

next build emits plain HTML/JS/RSC payload files deployable anywhere. Server components still work, but they run once at build time, not per request.

You lose everything that needs request-time code:

  • Dynamic SSR (cookies(), headers(), uncached dynamic data)
  • Server actions
  • Dynamic route handlers
  • Middleware
  • ISR / revalidation
  • Default image optimization

If you use any of these → serverless (Vercel, Netlify), edge, or next start on a Node host.
