Claude Code Orchestration

Claude Code offers four distinct approaches for parallelising or delegating work, each optimised for different scenarios. They vary in isolation, token cost, and coordination model.

See also: Claude Code Hooks, Claude Code Settings, Claude Code Memory and Context

Four Approaches at a Glance

ApproachBest ForIsolationToken CostRequires
SubagentsFocused tasks where only the result mattersOwn context windowLowNothing extra
Background SessionsMultiple independent tasks; monitor progressOwn worktreeMediumLocal machine
Agent TeamsParallel collaboration; competing hypothesesOwn worktree per teammateHighExperimental flag
RoutinesScheduled, unattended, repeatable tasksCloudBilled per runClaude.ai account

1. Subagents

Subagents run inside the current session. They get their own context window, do focused work, and report results back to the caller — you only see the summary, not the full transcript.

Define in .claude/agents/<name>.md (project) or ~/.claude/agents/<name>.md (personal):

Frontmatter Fields

FieldDescription
nameDisplay name
descriptionWhen to use it (used for auto-selection)
toolsAllowlist of permitted tools
modelModel override
mcpServersMCP server names to attach
isolationworktree to run in an isolated git worktree
permissionModeplan, default, acceptEdits, auto, etc.
skillsPreload skills into this subagent
forceNoClaude.mdSkip CLAUDE.md loading (used for Explore/Plan agents)

Invoke by describing the task naturally:

Create a subagent to research the authentication flow
Spawn a researcher to investigate the performance regression

2. Background Sessions (Agent View)

Full Claude Code sessions running in the background, each isolated in its own git worktree to prevent file conflicts. The supervisor process keeps them alive even when the terminal closes.

Commands

Session States

StateMeaning
WorkingActively running tools
Needs inputWaiting on your decision
IdleReady for next prompt
CompletedTask finished successfully
FailedEnded with error
StoppedUser-stopped

Key features:

  • Peek panel: view latest output without full transcript
  • Pin sessions to keep them alive when idle
  • PR status indicators in the agent view
  • Each session in its own git worktree — no file conflicts

3. Agent Teams (Experimental)

Multiple full Claude Code sessions that communicate with each other — not just back to a lead. Teammates self-claim tasks from a shared task list and message each other directly.

Enable:

Or in Claude Code Settings:

Architecture

  • Team lead — the main session; creates the team and coordinates
  • Teammates — independent sessions; each claims tasks from the shared list
  • Task list — lives at ~/.claude/tasks/{team-name}/; tasks have dependencies
  • Mailbox — messaging system between agents (Shift+Down to cycle teammates)

Usage

Create an agent team to review PR #142. Spawn three reviewers:
- One focused on security
- One checking performance
- One validating test coverage

Ask the researcher teammate to shut down
Clean up the team

Display Modes

ModeDescription
in-processAll teammates in main terminal (default)
tmuxSplit panes (requires tmux or iTerm2)
autoAuto-detects environment

Blocked tasks cannot be claimed until their dependencies complete. Teammates send updates automatically — the lead doesn’t poll.

4. Routines (Cloud-Based Scheduled Automation)

Routines run on Anthropic-managed cloud infrastructure. Your local machine doesn’t need to be running. Each execution creates a viewable session.

Three Trigger Types

Scheduled — cron intervals (minimum 1 hour) or presets:

/schedule daily at 9am, review open PRs and post a summary
/schedule weekdays at 6pm, check for failing CI and alert

API — HTTP POST to fire on demand:

POST https://api.anthropic.com/v1/claude_code/routines/{routine_id}/fire

GitHub — fires on PR or release events, with optional filters:

  • Author, title pattern, branch, labels, draft status

Slash Commands

/schedule                  # List routines
/schedule <description>    # Create a new routine
/schedule update           # Edit an existing routine
/schedule run              # Trigger a routine immediately

Configuration (Web UI)

  • Name and prompt
  • GitHub repository connections
  • Cloud environment settings
  • Multiple triggers on the same routine
  • Connectors (Slack, etc.) and permissions

Full autonomy — routines run without permission prompts, so pre-approve operations in Claude Code Settings before relying on them.

Token Cost Tradeoffs

Single session < Subagents < Background sessions < Agent teams
  • Single session — lowest; everything in one context window
  • Subagents — low-medium; results summarised back to caller
  • Background sessions — medium; isolated contexts but sequential per session
  • Agent teams — high; multiple full contexts + inter-agent communication overhead

Choosing the Right Approach

Use subagents when:

  • The task is focused and self-contained
  • You only care about the result, not the process
  • You want to preserve context in the main session

Use background sessions when:

  • You have multiple independent tasks to dispatch
  • You want to monitor progress without being blocked
  • You might context-switch between tasks

Use agent teams when:

  • Teammates genuinely need to discuss and iterate
  • Parallel exploration of competing hypotheses adds value
  • You have 3–5 complex tasks that benefit from coordination

Use routines when:

  • The task is scheduled and repeatable
  • You don’t need your laptop running
  • You need GitHub or CI/CD integration
