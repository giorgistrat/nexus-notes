React Suspense

Notes on Suspense-based data fetching in React — from EpicWeb’s React Suspense workshop by Kent C. Dodds, plus outside research.

The short version of how the pieces fit together: a component calls `use(promise)`. If the promise is still pending, use throws it; React catches that throw and renders the nearest `<Suspense>` fallback until the promise settles. If the promise rejects, use throws the rejection reason instead, and the nearest ErrorBoundary catches that. Both of these throws only work because a Promise is just a regular JS value — nothing stops you from throwing one.

use(promise)
  ├─ fulfilled → return value synchronously
  ├─ pending   → throw promise   → caught by <Suspense fallback>
  └─ rejected  → throw reason    → caught by <ErrorBoundary fallback>

Notes

Notes are grouped into a subfolder per workshop module.

Data Fetching (exercise 1)

  • JavaScript Promises — what a Promise is, its state machine, .then/.catch, the microtask queue, and the “a promise is just a throwable value” fact everything else here depends on.
  • The use Hook — how use synchronously unwraps a promise by throwing, React’s implicit try/catch around rendering, and a hand-rolled implementation built step-by-step in the workshop.
  • Suspense and ErrorBoundary for Data Fetching — the declarative boundary components that catch what use throws, why ErrorBoundary wraps Suspense rather than the reverse, and the full workshop code progression.

Dynamic Promises (exercise 2)

  • Promise Caching — why calling a fetch function directly during render breaks use/Suspense, and how caching the promise itself (a module-level variable, or a Map keyed by id) fixes it.
  • useTransition and Avoiding Loading Flicker — keeping the old UI visible during a suspending update with useTransition, and eliminating flash of loading state on top of that with useSpinDelay.

Optimistic UI (exercise 3)

  • useOptimistic Hook — updating state during a transition (which useState can’t do) to show a provisional result immediately, with a built-in fallback/rollback once the transition settles.
  • useFormStatus — reading a <form>’s submission status (pending, data, method) from a child component, and how it complements useOptimistic.

See also use and createContext (use for context, not promises) and Error Boundaries (the general ErrorBoundary API beyond the Suspense-specific usage covered here).
