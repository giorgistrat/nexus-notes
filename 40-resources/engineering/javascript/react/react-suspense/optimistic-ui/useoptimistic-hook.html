useOptimistic Hook

Notes from EpicWeb’s React Suspense workshop by Kent C. Dodds (exercise 3, “Optimistic UI”, steps 1 and 3). Assumes useTransition and Avoiding Loading Flicker — useOptimistic only makes sense once you know what a transition is and why it hides intermediate UI.

Interview Q&A

Q: What is “optimistic UI”? A: A general UI pattern usable in any app or framework: updating the screen immediately, assuming an action will succeed (which it usually does), rather than waiting for the server to confirm it first — e.g. a like button turning red the instant you click it, before the network request even resolves, or a chat message appearing right away before the server has actually stored it. The point is to make the app feel instant even when the network isn’t. In our example, a newly submitted ship appears on screen immediately, before the create-and-fetch round trip actually finishes.

Q: Why doesn’t plain useState work for optimistic UI inside a form action? A: This follows from a general rule about transitions, not something specific to forms or ships: Form actions run inside a transition automatically, and React holds back UI updates that happen during any transition until it finishes — so a regular setState call wouldn’t render until the whole action completes, defeating the point of showing something immediately. This applies just as much to a startTransition(() => {...}) you write by hand as it does to a form action.

Q: How does useOptimistic solve this, and what’s its first argument? A: useOptimistic is a general-purpose hook for any state that needs to update during a transition, unlike useState. Its first argument isn’t really an “initial” value — it’s the fallback value the state reverts to once the transition ends, whether the action succeeded or failed. In our example, that fallback is null (no optimistic ship) and, for the multi-step message, the string 'Create':

Q: How do you get automatic rollback on failure with useOptimistic? A: This “rollback” behavior is a general property of the hook, not something you implement yourself: once the transition ends, the optimistic value disappears and the component re-renders based on the real data, whatever it is. If the update failed (or the real data didn’t change), the UI just reverts to whatever the real data still says — you get correctness for free by falling back to the source of truth. In our example, if creating the ship failed, optimisticShip would fall back to null and ShipDetails would go back to suspending on the real (unchanged) ship list.

Q: Can you update optimistic state more than once during a single action? A: Yes, and this generalizes to any multi-step async process (checkout flows, multi-stage uploads, wizards) — since optimistic state is allowed to render during the transition, you can call the setter multiple times to show progress through a multi-step action, falling back to the initial value once the whole action finishes. What “optimistic UI” means

Most user actions succeed. Optimistic UI leans into that: instead of waiting for the server to confirm an action before updating the screen, you update the screen immediately, assuming success, and only correct course if the request actually fails. Liking a post on social media and seeing the heart turn red instantly — before the network request even resolves — is the classic example.

Why useState doesn’t work here

Form Actions (the action={...} prop on a <form>) run inside a transition automatically. As covered in useTransition and Avoiding Loading Flicker, React holds back UI updates that happen during a transition until the transition finishes — that’s the whole point of a transition, it’s what keeps the old UI visible while new data is being fetched.

That means a plain setState call inside a form action won’t show up on screen until the entire action finishes — which defeats the purpose of optimistic UI entirely. You need a way to update state that’s allowed to render during a transition. That’s what useOptimistic is for.

useOptimistic: state that updates during a transition, then falls back

useOptimistic looks like useState, but its first argument isn’t really an “initial” value — it’s the fallback value the state reverts to once the transition ends (whether it succeeded or failed):

What happens on submit:

  1. The form action runs inside a transition.
  2. setIsComplete(!isComplete) updates the optimistic state — and unlike a regular setState call, React does let this render immediately, so the checkbox flips right away.
  3. await updateTodo(...) does the real work in the background.
  4. Once the transition finishes, the optimistic value disappears and the component re-renders based on todo.isComplete again. If the update succeeded and todo reflects the new state, nothing visibly changes. If it failed (or todo didn’t update), the checkbox reverts — that’s the “rollback” of optimistic UI, and you get it for free just by falling back to real data.
